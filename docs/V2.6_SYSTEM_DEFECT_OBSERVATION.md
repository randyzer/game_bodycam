# V2.6 System Defect Observation

## Status

- Classification: SYSTEM DEFECT CANDIDATE — SOP / STARTER CONTRACT
- Project: Bodycam V2.6
- Date: 2026-09-07
- Bodycam impact after local repair: non-blocking
- Frozen authorities modified: no

## Observed Mismatch

The approved Bodycam planning artifact is `docs/MEDIA_DECISION_TABLE.md`.

The frozen Starter v2.6 validation entrypoint checks only project-root `MEDIA_DECISION_TABLE.md` when deciding whether to run media readiness validation.

Starter v2.6 also expects a narrow technical table with locator, `Priority`, and `Status` columns, while SOP/Master Prompt v2.6 define the Human-authored lifecycle table with fields such as `pageId_or_route`, `media_need`, `integration_state`, `human_decision`, `rights_state`, and `visual_gate_state`.

## Frozen SOP / Master Expectation

SOP and Master Prompt v2.6 place the media lifecycle artifact in the project documentation set as `MEDIA_DECISION_TABLE.md`, with lifecycle ownership outside Runtime Page Inventory.

The SOP lifecycle table requires route/page identity, media need, candidate state, rights state, Human decision, integration state, visual gate state, source/provenance, defer owner, and notes.

Runtime Page Inventory remains publication SSOT; the media table is planning/reconciliation support only.

## Frozen Starter Expectation

Starter v2.6 implements a lightweight optional readiness reader for a root-level `MEDIA_DECISION_TABLE.md` and a narrow readiness schema:

- `Page ID` or `Route`
- `Priority`
- `Status`
- optional `Rationale`

It treats absence of the root file as backward-compatible.

## Bodycam Reproduction Evidence

- Bodycam had `docs/MEDIA_DECISION_TABLE.md`.
- Bodycam did not have root `MEDIA_DECISION_TABLE.md`.
- `npm run validate` previously passed without consuming the approved docs artifact.
- Parsing the approved Bodycam lifecycle table through the Starter narrow parser produced deterministic missing-column errors instead of readiness decisions.

## Project-Local Repair

Bodycam now uses a local compatibility adapter at `scripts/bodycam-media-readiness.ts`.

The adapter:

- consumes `docs/MEDIA_DECISION_TABLE.md`;
- rejects a duplicated root `MEDIA_DECISION_TABLE.md` when the docs artifact exists;
- normalizes only the readiness fields the technical gate needs:
  - `pageId_or_route`
  - `media_need`
  - `integration_state`
  - optional `need_rationale`
- maps `NOT INTEGRATED` to unresolved readiness;
- maps `INTEGRATED` and `FALLBACK ONLY` to resolved readiness;
- preserves Runtime Page Inventory as publication SSOT;
- avoids parsing Human risk acceptance, visual approval, rights ownership, or full lifecycle state into publication logic.

## Why Frozen V2.6 Was Not Modified

The frozen Starter, SOP, and Master Prompt authorities are read-only for this Bodycam local repair.

This project-local adapter repairs Bodycam validation without changing the frozen v2.6 baseline or widening Starter architecture.

## Recommended Future Disposition

Address in v2.6.1 or v2.7 by aligning the Starter readiness input location/schema with the SOP/Master media lifecycle artifact, or by documenting the expected project-local adapter pattern.

Do not use this Bodycam-local compatibility adapter as an implicit upstream change without a separate frozen-system review.
